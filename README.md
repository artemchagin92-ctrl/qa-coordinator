# QA Coordinator

Python-координатор проверяет результат работы агента перед тем, как передать задачу на ручной ретест. В репозитории собраны модули рабочего QA-бота и локальный стенд с вымышленными задачами.

## Что можно проверить

1. Координатор читает задачу и запоминает её ID и хеш исходных данных.
2. Сверяет изменения в Git и команды из журнала агента с отчётом исполнителя.
3. Сверяет ревизию выпуска и контрольную сумму файла. Перед записью перечитывает очередь и проверяет, что задача не изменилась.
4. Принимает результат на ручной ретест, если проверки прошли. Падение теста или изменение задачи оставляет статус прежним.

Локальный стенд создаёт временный Git-репозиторий, запускает настоящий тест Node.js и записывает его код завершения в событие формата Codex CLI. Очередь и отчёт исполнителя подготовлены заранее. Координатор принимает журнал команд и подтверждение выпуска через адаптеры, которые в этом запуске работают локально. Вместо подключения к Google Sheets и выпуска на сервер стенд записывает состояние локально и сверяет файл в тестовом каталоге выпуска.

## Запуск

Нужны Python 3.11+, Git и Node.js 18+. Внешние Python-пакеты не требуются.

```bash
python3 -B coordinator.py --scenario ready
python3 -B coordinator.py --scenario test-failed
python3 -B coordinator.py --scenario row-changed
python3 -B -m unittest discover -s tests -v
```

## Демо в браузере

[Открыть демо на GitHub Pages](https://artemchagin92-ctrl.github.io/qa-coordinator/). Первый пример показывает, когда QA-задача доходит до ретеста. Второй переносит ту же идею проверок на заполнение таблицы по акту. Обе демонстрации работают в браузере на вымышленных данных.

```bash
python3 -m http.server 4398 --bind 127.0.0.1 --directory docs
```

Откройте [localhost:4398](http://127.0.0.1:4398/). Тесты примеров можно запустить командой `node --test demo-tests/*.test.mjs`.
